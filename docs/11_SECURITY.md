# 安全与隐私

本项目处理的资料可能包含：
- 身份证信息；
- 银行流水；
- 工资；
- 社保；
- 私人聊天记录；
- 劳动合同。

## 必须做到

1. HTTPS。
2. 密码不明文存储。
3. API Key 仅服务器保存。
4. 文件访问必须鉴权。
5. 文件名不得直接作为授权依据。
6. 防止路径穿越。
7. 上传文件 MIME 与扩展名双重校验。
8. 限制文件大小。
9. 日志脱敏。
10. 数据库最小权限。
11. 删除采用软删除并提供彻底删除策略。
12. AI provider 不得默认将用户数据用于训练；如第三方服务政策不同，必须在产品中明确说明。
13. 导出文件访问使用短期签名 URL 或受控下载接口。
14. 跨源访问必须走 CORS 白名单（`cors_allow_origins`，默认仅本地前端地址），
    且不启用 credentials——JWT 经 `Authorization` 头传递（localStorage），不使用
    Cookie，因此拒绝带凭证的跨源请求。暴露给浏览器的响应头仅
    `Content-Disposition` 与 `X-Request-ID`。

## 不应该做

- 在浏览器 localStorage 保存敏感原始材料；
- 把完整银行账号写入日志；
- 把完整身份证号写入错误日志；
- 将原始文件内容直接作为 analytics 数据发送第三方。

## 威胁模型

至少测试：
- 越权读取其他案件；
- 任意文件下载；
- 路径穿越；
- 恶意 PDF；
- 超大文件；
- XSS；
- CSRF；
- SQL injection；
- prompt injection；
- AI 输出中的恶意内容。
