# PRD — 产品需求文档

## 1. 用户问题

普通人遇到劳动争议时，往往已经拥有大量材料，但材料具有以下特点：
- 来源不同；
- 格式不同；
- 时间顺序混乱；
- 同一事实可能分散在多个截图中；
- 用户不知道哪些材料应该放在一起；
- 不知道如何给证据命名；
- 不知道“证明目的”怎么写；
- 不知道最终如何装订。

产品解决的是“证据整理成本”，而不是替用户作法律决定。

## 2. 用户画像

### P0 普通劳动者
特点：
- 没有法律专业背景；
- 手机里有大量聊天截图；
- 有工资、合同、考勤等材料；
- 希望快速形成清晰材料。

### P1 律师/法律服务人员
特点：
- 需要处理大量底层材料；
- 希望减少 OCR、分类、编号和排版时间。

## 3. 核心用户故事

### US-001 创建案件
作为用户，我可以创建一个案件，并填写案件名称和简单描述。

验收：
- 创建成功；
- 可编辑；
- 可删除；
- 有创建时间和更新时间。

### US-002 批量上传
作为用户，我可以一次上传多个文件。

验收：
- 支持拖拽；
- 显示上传进度；
- 单个文件失败不影响其他文件；
- 文件状态可见。

### US-003 AI 解析
系统自动识别：
- 文档类型；
- 日期；
- 金额；
- 人物；
- 公司/组织；
- 事件；
- 摘要；
- 证明目的建议。

### US-004 人工确认
用户能够查看原始文件和 AI 结果，并逐项修改。

### US-005 时间轴
系统根据事件生成案件时间轴。

### US-006 证据目录
系统根据确认后的 Evidence 自动生成证据目录。

### US-007 导出
用户可以生成：
- DOCX
- PDF
- ZIP

## 4. 非功能需求

### 性能
- 普通页面首屏目标 < 2 秒（不含 AI 任务）
- 上传使用异步处理
- AI 任务不得阻塞 Web 请求。

### 可用性
- AI 处理失败必须允许重试。
- 用户关闭浏览器后任务仍可继续。
- 所有审核状态持久化。

### 安全
- 原始文件与派生数据分离。
- 文件下载必须经过权限校验。
- 不在前端暴露 AI API Key。
- 日志不得记录完整身份证号、银行卡号等敏感信息。
